Requirements, keys and command lines

Everything you look up rather than read: what you need installed, every default shortcut, the headless command lines, the build options and the renderer model.

Requirements

You needWhy
A C++23 compiler — GCC 13+, Clang 16+ or MSVC 19.38+Studio and CNA are both C++23
CMake ≥ 3.20Studio drives your project's CMake; it never generates a build system of its own
A CNA checkoutOnly to build a game, or to get the scene viewport. Studio itself builds without one

You do not need a GPU, a display, or any of CNA's sibling checkouts to build and run Studio. The default build has no external dependencies at all: 1832 assertions across 69 CTest cases, in about a minute and a half.

Running without a window

Headless mode is not a lesser Studio: it opens projects, reads scenes, creates projects from templates and exports them, with no GPU and no display. 

cna-studio --list-templates
cna-studio --new-project=DIR --template=ID --project-name=NAME
cna-studio --project=FILE --headless --frames=N
cna-studio --project=FILE --export=DIR
cna-studio --ui-benchmark        # what a frame of UI costs, per panel
cna-studio --host-capabilities   # what Studio requires of a host renderer
cna-studio --list-backends       # the CNA graphics backends this build knows about
cna-studio --help                # the rest

Photographing the interface

Studio can render its own shell to a PNG with no graphics device at all. This is how the panel close-ups on these pages were taken, and how the visual regression suite runs on every commit: 

# the whole shell
cna-studio --shell-preview=shell.png --shell-size=1920x1080 --shell-theme=dark \
           --project=examples/HelloSprites/HelloSprites.cnaproject --select=Player

# one panel, filling the frame, for a page taller than its dock
cna-studio --shell-preview=build.png --shell-size=1500x510 --shell-panel-only=build \
           --project=examples/HelloSprites/HelloSprites.cnaproject

A real window screenshots itself too, which is where the wide captures on these pages come from — that one needs a display and a GL driver, and Xvfb plus Mesa's software rasteriser is enough: 

cna-studio --project=examples/HelloSprites/HelloSprites.cnaproject --select=Player \
           --window-size=1600x900 --frames=8 --workspace=none --screenshot=shell.png

Building Studio

git clone https://github.com/libcna/cna-studio
cd cna-studio
cmake -S . -B build -G Ninja
cmake --build build -j4
ctest --test-dir build

With the CNA viewport

cd ..
git clone https://github.com/libcna/cna.git
git clone https://github.com/libcna/sharp-runtime.git
cd cna-studio

cmake -S . -B build-cna -DCNA_STUDIO_WITH_CNA=ON -DCNA_DEVICES=ON

CNA itself needs SDL3's build dependencies plus FFmpeg headers; -DCNA_DEVICES=ON is what gives Studio a working clipboard. The root README.md lists the exact Debian package names.

Renderers and platforms

A build target names two independent things: a CNA platform — the windowing and input layer, one of SDL3, SDL2, headless or terminal — and a CNA renderer, the graphics backend.

Studio classifies the fifty renderer identities CNA publishes rather than keeping a list of its own, and a guard test refuses any code outside that catalogue that names a renderer: a hard-coded backend name stops being true the next time CNA adds one, silently, because an unknown renderer looks exactly like a renderer the user did not pick. When CNA adds an identity, Studio's test suite fails and names it. That failure is the notification.

The renderer Studio draws itself with and the renderer your game targets are unrelated. A machine that cannot run Vulkan can still build a Vulkan game, and a Studio that refused would be wrong. Studio's own requirement is a separate question, and cna-studio --host-capabilities answers it.
