# C++ deviations from upstream Myra

This document records only necessary, tested differences from the selected
upstream `Myra.FNA.Core` behavior. A difference is not accepted merely because
it is more convenient in C++.

| ID | Upstream behavior | C++ mapping | Rationale | Test | Status |
| --- | --- | --- | --- | --- | --- |
| DEV-001 | C# properties | `getXProperty()` / `setXProperty()` | Established CNA/sharp-runtime C++ surface convention; behavior remains equivalent. | API inventory | Planned |
| DEV-002 | Runtime reflection drives MML/PropertyGrid/DataGrid | Explicit Myra type/property registry | sharp-runtime intentionally has no usable .NET reflection. `TypeRegistry` now covers explicit type/XML registration, factories, typed getter/setter adapters, inheritance, defaults, and Myra metadata. Attached-property base-type discovery uses that same registry and a C++ layout-invalidation hook preserves the upstream ordering. Codecs, loading, and editor integration remain pending. | `TypeRegistryTests.*`, `AttachedPropertiesRegistryTests.*`, `WidgetTests.AttachedPropertyOptionsInvalidateTheMatchingLayoutPhase` | Accepted foundation |
| DEV-003 | `Thickness.FromString(null)` returns `Thickness.Zero`; invalid numeric parts throw .NET format exceptions. | C++ accepts `const std::string&` (not null) and throws `std::invalid_argument` for all invalid text. | C++ has no null string value and does not expose .NET exception types. Valid parse and layout behavior remain identical. | `ThicknessTests.*` | Accepted |
| DEV-004 | Myra event delegates accept `object sender`; C# classes can be passed and event-argument objects remain mutable to handlers. | `MyraEventHandler` uses sharp-runtime `System::MulticastAction<void*, T&>`. | CNA/Myra classes do not derive from sharp-runtime's abstract `System::Object`; a raw non-owning sender preserves unconstrained C# sender behavior, and `T&` preserves cancellation/value mutation. | `EventsTests.GenericHandlerSupportsMutationAndTokenRemoval` | Accepted |
| DEV-005 | C# permits `CancellableEventArgs` and `CancellableEventArgs<T>` in one namespace. | The generic C++ type is `CancellableEventArgsT<T>`. | C++ cannot declare a class and a class template with the same name in one namespace. | `EventsTests.ArgumentsPreserveUpstreamValuesAndMutability` | Accepted |
| DEV-006 | `Mathematics.PointZero` is a static initialized C# field. | `Mathematics::getPointZeroProperty()` constructs and returns the zero `Point` on demand. | Avoids a CNA `Point` linker dependency merely from including an otherwise header-only utility header in headers-only CMake mode. | Header compile via `myra_cna_minimal` | Accepted |
| DEV-007 | `ColorHSV.Equals` compares `a.S` with `b.V`, making many values unequal to themselves. | The same comparison is retained. | This is an observable upstream defect; changing it would break strict behavior parity and must be a separately approved compatibility change. | `ColorHSVTests.PreservesTheSelectedUpstreamEqualityBehavior` | Accepted upstream defect |
| DEV-008 | `StringUtils.Length` accepts nullable C# `string` and returns zero for null or empty. | `StringUtils::Length` accepts `const std::string&`; empty returns zero. | Standard C++ has no null string object. | `StringUtilsTests.*` | Accepted |
| DEV-009 | `IItemWithId.Id` is a nullable C# `string`. | `getIdProperty()`/`setIdProperty()` use `std::optional<std::string>`. | Unlike a bare C++ string, the optional precisely preserves the distinction between upstream `null` and the empty identifier. | `BaseObjectTests.IdPreservesNullEmptyAndValueChanges` | Accepted |
| DEV-010 | `IContent.Content` and `ILayout` use garbage-collected `Widget` references/`IEnumerable<Widget>`. | Their C++ contracts use `std::shared_ptr<Widget>` and `std::vector<std::shared_ptr<Widget>>`. | This is the project-wide public collection/ownership model; parents will retain the owning collection while parent links remain non-owning. | `WidgetContractsTests.ContentAndLayoutUseSharedWidgetCollections` | Accepted |
| DEV-011 | C# `ObservableCollection<Widget>` can technically retain the same widget in several parent collections, leaving its `Parent` property ambiguous. | `Widget::AddChild` first removes a child from its old parent. | The project must retain one unambiguous owner and one non-owning parent link; this prevents stale-tree input, layout, and destruction behavior. | `WidgetTests.ChildrenHaveOneParentAndAreStablyOrderedByZIndex` | Accepted |
| DEV-012 | `SingleItemLayout<T>` accepts a nullable C# `Widget` constructor parameter and throws for null. | Its C++ constructor accepts `Widget&`. | A reference makes the required non-null container contract explicit and cannot represent an invalid layout instance. | `SingleItemLayoutTests.*` | Accepted |
| DEV-013 | `RangeAttribute` and `XmlNameAttribute` throw .NET `ArgumentException` for invalid constructor values. | They throw `std::invalid_argument`. | The invalid input and rejection point remain the same; C++ does not expose .NET exception types. | `AttributeMetadataTests.RangePreservesOptionalBoundsAndRejectsAnInvertedRange`, `AttributeMetadataTests.StylePathAndXmlNamePreserveAndValidateNames` | Accepted |
